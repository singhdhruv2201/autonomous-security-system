# Security and evaluation boundary

Autonomous Security System is a local prototype using synthetic Helio data. It is
not a production security service, a supported enterprise deployment, or permission
to test Awasi's real systems. Use it only within the evaluation rights in [LICENSE](LICENSE).

## Report a problem privately

Contact Dhruv Singh through the private correspondence used to share the repository.
If you do not have a private contact channel, request one through the
[owner's GitHub profile](https://github.com/singhdhruv2201) without publishing exploit
or credential details. No response-time or vulnerability-bounty commitment is made.

Include the affected commit, reproduction steps using synthetic data, expected and
actual behavior, and the relevant service. Do not include API keys, Slack tokens,
real customer data, raw private traces, or an unredacted `.env` file in issues,
pull requests, screenshots, or logs.

## Operating guidance

- Keep services bound to localhost. The showcase's browser decisions are local
  demo controls, not production identity or access management.
- Use distinct observer and action credentials, generated by the documented setup.
  Keep credentials and runtime databases out of Git.
- Enable live model/Slack operation deliberately and preserve usage ledgers.
- Test uncertain writes, authorization failures, and recovery paths. A successful
  request is not proof that the intended state was verified.
- Review [known limitations](docs/known-limitations.md) before extending deployment
  scope. Dependency locks improve reproducibility; they are not a security audit.
